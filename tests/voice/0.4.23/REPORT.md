# 0.4.23 同场继承与 Claude 亮签参考

上一版七轮验证使用预先指定的角色。此次检查的是首次暗抽后续聊、助手身份前后冲突和亮签使用的作品。基线 0.4.22 在已安装插件与 GitHub 的技能正文一致。旧版把“首次启用”列作抽签入口，又允许中途补抽，未写清助手未经用户授权自行串角后的恢复顺序。文本检查不能单独确定用户宿主上的失效机制。

改动覆盖首次建签、续轮读取、残缺记录、只改一项和亮签查询。首次建签时选取缺省维度；其后先按本线程内首次已知身份、用户明确执行的变更还原有效签。角色不能从示例、另一身份的自称或一次错误亮签自行改写。无法确认的字段明示缺项，询问用户还原或补抽。README 同步调整了安装偏好与验证步骤。

## 显式加载下的独立试验

| 场景 | 观察到的结果 |
|---|---|
| 新会话不指定角色或脾气，默认暗抽后普通追问，再亮签 | 首轮与次轮均沿用哈基米，亮签为 Gemini＋抽象。再只换主脾气，得到 Gemini＋冷幽默。初始脾气没有在首轮公开，无法独立从首轮文字核验其抽取。 |
| 合成已有会话中先明确使用鲸鱼娘自称，之后助手未经用户同意变为大小姐并错误亮签 | 查询得到 DeepSeek 鲸鱼娘，主脾气无法确认。下一句继续以本鲸回答。 |
| 已有 DeepSeek＋冷幽默，用户明确只换角色为 Claude，查标准立绘 | 输出 Claude＋冷幽默，提供角色档案、对应作者原帖、作品标题及外观辨认点。 |

## 图源核对与范围

已打开[角色档案](https://genderswapai.com/zh-CN/ai-gijinka/claude)中署名 ZipZipPipe 的“Claude 娘 · 角色立绘”，核对橙色长发、花朵发饰、黑白层叠裙装。[作者原帖](https://www.bilibili.com/opus/1233069202138464289)收录多位角色。默认按档案中的指定单人作品辨认。无法核对时用文字签和档案链接。

本轮没有取得故障客户端实际渲染图，没有测试手机端自动加载或真实亮签卡片出图，也没有生成新图。实现使用可见会话上下文；本轮没有新增宿主持久化接口。正式 ZIP 的三个入口均已解包比对，YAML、manifest 版本和完整性检查通过。
