**浅拷贝只新建外层容器，里面的对象仍然共享；深拷贝会递归复制内部对象。** 本龙带你盯住“改的是哪一层”，这个问题就不会绕成一团。另一个要先分清的东西是赋值：`b = a` 连外层都没复制，只是让两个名字指向同一对象。

先看这段嵌套列表，下面的输出按代码语义推导，未执行：

```python
import copy

a = [[1, 2], [3, 4]]
b = copy.copy(a)
c = copy.deepcopy(a)

print(a is b, a[0] is b[0])
print(a is c, a[0] is c[0])

b[0].append(9)
b.append([5, 6])
c[1][0] = 30

print(a)
print(b)
print(c)
```

预期输出：

```text
False True
False False
[[1, 2, 9], [3, 4]]
[[1, 2, 9], [3, 4], [5, 6]]
[[1, 2], [30, 4]]
```

先看前两行，`is` 比较的是对象身份。`a` 和 `b` 是不同的外层列表，但它们的第一个元素指向同一个内部列表。`c` 的外层和内部列表则都是独立的。（外壳换了，里面还是同一份东西，浅拷贝倒也没隐瞒。）

接着追三个修改。`b[0].append(9)` 改的是共享的内部列表，所以 `a` 也能看到这个 `9`。`b.append([5, 6])` 改的是 `b` 自己的外层结构，`a` 不会多出一行。至于 `c[1][0] = 30`，改的是深拷贝中的内部列表，自然不影响原来的 `a`。你看，不能只凭“我操作的是 b”就断言跟 a 无关，得再往下一层看。

选哪种，本龙会先看你准备怎么改：

- **只增删、排序外层元素**，内部对象允许共享：用浅拷贝，通常更省时间和内存。对列表，`a.copy()`、`a[:]`、`list(a)` 也都是浅拷贝。
- **要修改内部列表，而且必须与原数据隔离**：用 `copy.deepcopy(a)`。别见到“深”就默认更高级；复制整个对象图也要付成本。
- **只想隔离某几个内部列表**：可以只复制需要修改的部分，但要明确其余部分仍可能共享。

还有几处容易踩坑，我给你拎出来。`b[0] = [8, 8]` 是替换 `b` 的外层槽位，不会改掉 `a[0]`；它和 `b[0].append(8)` 不是同一回事。`==` 判断内容相等，也不能证明两个对象互相独立。

最后，深拷贝并不保证“所有东西都变成新对象”：整数、字符串等不可变对象可以复用，自定义对象还能定制复制行为。它也会记录已经复制过的对象，处理循环引用并保留原有的共享关系。（复制得深，不等于把每条引用都拆散。）真正该确认的是：**后续要修改的可变对象，是否仍被两边共享。**
