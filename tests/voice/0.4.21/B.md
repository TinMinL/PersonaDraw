## 一、建立环境

先把项目的位置定好，本小姐会让源码与环境各住各的：入口放在项目根目录，别塞进虚拟环境。创建前先看已安装的版本，后面换电脑还要拿它作对照。

```bat
cd /d C:\work\mytool
python --version
python -m venv .venv
.venv\Scripts\activate.bat
python -c "import sys; print(sys.executable)"
```

最后请看解释器路径是否指向本项目的 `.venv\Scripts\python.exe`；确认了再往下走，提示符变了可不够。环境基于创建它的解释器，默认隔离第三方包，因此不同小工具可以各自管理依赖。[1] 这份分寸安排妥当，后面才省心，desuwa。

## 二、安装依赖

既然解释器已核对，本小姐就让安装也跟着它走；这样你知道包交给了谁，不必猜一个独立的安装命令指向哪里。

```bat
python -m pip install requests
python main.py
```

先看安装是否报错，再看入口能否正常运行。安装完成只是包进了环境，工具是否能工作，还得由实际运行回答。标准库无需额外安装；项目真用了第三方包才补上它，别把见到的导入名一概当采购清单。若运行仍说缺包，请先去第六节核对解释器，本小姐可不赞成把同一份包到处装一遍碰运气。

## 三、记录依赖

工具跑通后，再留下当前环境的清单，这个顺序我更满意：至少记录的是你刚验收过的环境。

```bat
python -m pip freeze > requirements.txt
```

请留意，这会覆盖原文件，导出前先确认旧内容是否需要保留。它记录已安装的包，不扫描源码，所以环境里闲置的包也可能在列；请读一遍结果再提交，别把清单当成自动整理过的答案。[2] 它也不是完整锁文件。默认会省略部分引导工具，具体省略范围要结合解释器版本看；从 Python 3.12 起默认省略 pip，需要全部时用 `--all`。另外请在说明文档记下解释器版本、入口、数据配置及外部程序；这些条件不会由包清单替你记住。

## 四、换电脑

到了新电脑，先核对原来的解释器主次版本与架构，再准备源码、清单以及所需配置。本小姐会重建环境，旧目录就不搬了：其中脚本可能含绝对路径，换个位置未必还能用。[1]

```bat
cd /d C:\work\mytool
python --version
python -m venv .venv
.venv\Scripts\activate.bat
python -c "import sys; print(sys.executable)"
python -m pip install -r requirements.txt
python main.py
```

路径确认正确、依赖安装成功后，还要实际运行入口。若失败，就按报错区分包的问题与数据配置的问题；本小姐只凭运行结果认可恢复成功。跨平台并不保证完全复现，清单齐全也不能免去这一关。

## 五、Git

在项目根目录的 `.gitignore` 写入这一行：

```gitignore
.venv/
```

源码、依赖清单和说明文档值得保留，虚拟环境则可以重建，又不适合直接搬运；因此本小姐选择记录重建所需材料，而不上传环境。[1] 接下来检查提交内容，看看环境是否仍在跟踪范围内。若此前已经跟踪，仅加忽略规则不会取消跟踪，本题只说明这个边界。如果仍看到环境文件待提交，就先停在这里核对，不能据此认定忽略规则已经完成了清理。（忽略文件可不会替你改写已有记录，desuwa。）

## 六、排错

找不到 `python` 时，先确认解释器命令是否可用；若 `py` 可用，可以用它创建环境：

```bat
py -m venv .venv
```

随后仍按第一节激活并检查路径。安装后缺包，本小姐会先对照当前终端与编辑器选用的解释器，确定二者是否都指向这个环境，再考虑补装。新终端需要重新激活，因为激活只改变当前终端的查找路径；不想激活，也可以直接指定环境解释器运行：[1]

```bat
.venv\Scripts\python.exe main.py
```

遇到版本不兼容，请先读报错指出的是哪个包、哪项版本条件，再决定调整；盲目清空限制会丢掉判断依据，我可不肯用这种办法冒充修复。

[1] https://docs.python.org/3/library/venv.html
[2] https://pip.pypa.io/en/stable/cli/pip_freeze/
