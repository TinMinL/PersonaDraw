# 0.4.22 每轮回应提醒与回归记录

## 审核范围

对照 0.4.21 已安装的三文件插件、仓库正式技能、README 默认偏好和 0.4.21 的报告。源码与已安装技能一致。此前已有“每轮都由当前角色直接回答”，且独立描述了工具返回、精确输出及整场暂停。维护上的缺口是简短续问、单轮严格格式后的接话、整场暂停的判定散在几处。此前的中段盲评结果有分歧，尚不能确认这处编排就是掉人设的原因。

## 改动

将已有每轮条款换成靠前的“每轮回应”。作答前在本线程识别当前签、最近变更和输出范围。可自由措辞时由角色讲本轮的一项实际判断及其理由。简短续问和进度说明同样适用。检查只在内部进行。严格格式优先，在下一次普通回复中接回当前签，整场暂停持续到明确恢复。README 的可复制偏好同时更新。插件没有定时器、逐轮注入接口或独立存储。

## 对照

两条独立的七轮会话，一条显式读取旧规则，一条显式读取新规则，同一组输入，同一角色 Claude 大小姐，主脾气温柔损友，少梗。对照仅覆盖以下场景。评阅者知道分组，未盲评。

| 轮次 | 观察项 | 0.4.21 | 0.4.22 |
|---|---|---|---|
| 1 | 两台设备的作业都有改动，建议第一步 | 保留两份，语气有照拂感 | 保留两份，接话落在时间戳的误导上 |
| 2 | “继续”追问两份结论如何取舍 | 按题目和证据判断 | 同样按证据和适用条件判断 |
| 3 | 只给一行 Python | 精确输出 print(sorted([3, 1, 2])) | 相同，无围栏和额外台词 |
| 4 | 转为十五分钟口语练习，给选择和改选条件 | 从开头开始，说明何时通读；原声线回归 | 先判断是否已通读，按卡顿和时间改选；原声线回归 |
| 5–6 | 明确暂停并指定确认语，接着继续问练习 | 确认语正确，后续朴素作答 | 相同 |
| 7 | 恢复角色、关旁评，参考两条排练记录给理由和验收方式 | 原角色恢复，无括号旁评，区分停顿位置与未知原因 | 原角色恢复，无括号旁评；练习针对抬头后接话，理由及建议都贴着记录 |

两个版本在这些转换上都达到了基本预期。新回复的第二段能在不使用括号的情况下延续照拂口吻。主脾气与普通耐心解释仍可能相似，单角色、每版本一条会话不足以说明新版本稳定优于旧版。没有在手机原生宿主、超长上下文或真正的工具返回后测试本轮表现。七轮是显式加载试验，不能证明宿主每轮自动加载技能。

发行前检查了 YAML、两个 manifest 的版本与保留字段，以及 ZIP 三个入口文件的完整性。
